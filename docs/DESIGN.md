## 1. 设计原则

由 PRD 的三条产品原则推出：

1. **帮人做决定，不堆选项。** 每屏只问一件事；推荐只给 3–5 道；每张卡片都写明“还要买什么”，让人能直接选定。
2. **单手、站着、手上可能有油。** 以手机竖屏单手操作为基准：主按钮固定在拇指够得到的底部；可点区域不小于 44×44pt；烹饪模式字号放大、按钮占满半屏。
3. **说清楚关键点，不写废话。** 步骤写判断标准（“炒到边缘微焦”）；文案简短，不用感叹号堆砌，不说“亲”。
4. **海外厨房优先。** 食材名旁附英文名，单位可切换，替代方案就近展示。
5. **等待时也有东西看。** 文字流式出现，图片后补；任何等待都有进度或骨架，不出现空白页。

## 3. 核心流程

### 3.1 已登录用户：从打开到推荐（目标 30 秒内）

```
首页（上次的口味已默认带出，F13）
 → 拍照，或点 3–5 个常用食材
 → 确认识别结果 / 勾选今天想用的主料
 → [下一步] → 口味页，默认带上次的选择，直接点 [给我推荐]
 → 推荐结果：首张卡片 5 秒内出现
```

### 3.2 未登录访客

```
首页 → 可以完整选好食材与口味（联想来自词典，不调用模型）
 → 点 [给我推荐] → 弹出登录层（三个入口）
 → 登录或注册成功 → 自动回到推荐页并开始推荐（F34），无需重选
```

拍照按钮对访客同样可见，点击后弹出登录层，文案说明“登录后可拍照识别食材”。

### 3.3 注册

```
登录层
 ├─ [使用 Google 继续]（最显眼）
 ├─ 邮箱 → 发送验证码 → 输入 6 位码
 │
 └─ 验证通过后：
     ├─ 已有账号 → 直接进入
     └─ 新邮箱 → “填写邀请码”页
          ├─ 填码 → 欢迎页（询问忌口与过敏，可跳过）→ 回到原来的页面
          └─ [没有邀请码？申请一个] → 留言（可选）→ “已收到申请”
```

不论邮箱是否注册过，发码后的提示都一样（PRD 4.6）。

## 4. 页面说明

线框图中 `[ ]` 为按钮，`( )` 为可选标签，`▢` 为图片。

### 4.1 首页 · 第一步：食材

```
┌──────────────────────────────┐
│ 小灶                今日剩 3 次│  ← 已登录才显示额度
│                              │
│ 今天手头有什么？              │
│ ┌──────────────────────────┐ │
│ │ 📷 拍一下冰箱或台面        │ │  ← 大按钮，F1
│ └──────────────────────────┘ │
│ ┌──────────────────────────┐ │
│ │ 🔍 输入食材，中英文都行     │ │  ← 联想，F7
│ └──────────────────────────┘ │
│ 常用  (鸡蛋)(鸡腿)(番茄)(土豆) │
│       (豆腐)(牛肉末)(洋葱)…   │
│                              │
│ 已选 4 样 · 点选今天想用的主料 │
│ [✓鸡腿] [✓土豆] [ 洋葱] [ 蒜] │
│                              │
├──────────────────────────────┤
│ [        下一步：选口味       ]│  ← 固定底部
└──────────────────────────────┘
```

- **已选食材**以标签显示，两种状态：主料（实心、带勾）和“手头还有”（描边）。点标签切换，长按或左滑删除。主料 1–5 个；新加入的前 3 个默认为主料。
- **常用食材**：未登录显示词典中的高频食材；登录后按个人历史排序。
- **联想**：输入时匹配中文名、别名、英文名（“芫荽 / cilantro / coriander”都出“香菜”）；词典外的词也能加入，以虚线标签显示。
- “下一步”在没有选任何食材时也可点（允许“只按口味推荐”），文案变为“跳过，直接选口味”。

### 4.2 拍照识别

1. 点“拍一下”：调用系统相机或相册，最多 3 张。首次使用先弹出说明：“照片会发送给模型服务商识别食材，识别后不保存。”[知道了]
2. 识别中：照片缩略图上覆盖扫描动画，文案“正在认食材…”。
3. 结果以标签列表回到第一步页面，分两组：
   - **认出来的**：默认已勾选。
   - **不太确定**：浅色、默认不勾选，点一下加入（F3）。
4. 顶部提示条：“认错了可以直接改：点标签改名，左滑删除。”
5. 失败或超时（8 秒）：提示“没认出来，手动输入也很快”，焦点自动落到输入框（F6）。照片里不是食物：“这张照片里好像没有食材，换个角度再拍一张？”

### 4.5 教程

**手机布局（从上到下）：**

1. 成品图（4:3），左上返回、右上收藏。下方小字：“AI 生成示意图，成品可能不同”。
2. **概览**：中文名（大标题）、英文名与原文名（次要字色）、菜系标签、一句风味描述；一行信息：总时间 · 动手时间 · 难度 · 份量。
3. **食材**：
   - 顶部控件：份量 `[−] 2 人份 [+]`、单位切换 `公制 | 美制`（F17）。
   - 分“主料 / 辅料 / 调料”三组；每行：中文名 + 英文名（次要字色）+ 右对齐用量。可省略的食材标“可省”。
   - 有替代方案的食材行尾带“替代”标记，点开就地展开替代建议和风味差别（F18）。
4. **步骤**：编号列表，每步一个动作。步骤内带火力徽标（如“中大火”）、时长（可点击开始计时）、**判断标准**以加粗显示，警告以浅色底提示框显示。
5. **关键点**：1–3 条，带图标的强调卡片，放在步骤之后、开始烹饪按钮之前。
6. **背景**（默认折叠）。
7. **安全提示**与免责说明（小字）。
8. 底部固定栏：`[ 问一问 ]  [ 开始做 → ]`。

**桌面布局（≥ 1024px）：** 左栏 320px 固定显示图片、概览和食材（随页面滚动时保持可见）；右栏显示步骤、关键点、背景。

**流式状态：** 概览与食材先出现，步骤逐条出现；未完成时底部按钮为“正在写步骤…”且不可点。

**追问（F20）：** 点“问一问”从底部弹出对话层，顶部是 3 个预置问题（“没有___怎么办”“能用空气炸锅吗”“能提前做吗”），输入框旁显示“还能问 4 次”。

### 4.6 烹饪模式

```
┌──────────────────────────────┐
│ ✕  第 3 步 / 共 7 步   食材 ☰ │
│ ━━━━━━━━━░░░░░░░░░░░░░       │
│                              │
│   中大火                      │
│                              │
│   下鸡腿块，                  │
│   煎到两面金黄。              │  ← 28px 起
│                              │
│   看到：表皮收紧、             │
│   边缘焦黄，不粘锅            │  ← 判断标准，加粗
│                              │
│   [ ⏱ 开始计时 6:00 ]         │
│                              │
├──────────────┬───────────────┤
│   ← 上一步    │   下一步 →    │  ← 各占半宽，高 72px
└──────────────┴───────────────┘
   ⏱ 鸡腿 4:12   ⏱ 米饭 11:30     ← 计时器悬浮条，可多个
```

- 一屏一步（F22）；左右滑动也可翻页。
- 进入即请求屏幕常亮（F23）；不支持时顶部显示一次提示。
- 计时器（F24）：可同时运行多个，悬浮条显示名称（取自该步骤的主食材）与剩余时间；到点振动 + 提示音 + 全屏闪烁提醒，点一下关闭。
- 右上“食材”打开底部弹层，显示完整食材清单与用量（F25）。
- 最后一步的“下一步”变为“做好了”，进入评价。
- 离线时完全可用；顶部不显示任何网络错误。
- 烹饪模式强制使用高对比配色，跟随系统深色模式。

### 4.7 评价

做好后从底部弹出：

```
做得怎么样？
[ 😋 好吃 ]  [ 🙂 一般 ]  [ 🙅 不会再做 ]
说一句原因（可选）：____________
[ 完成 ]
```

- 只点一下即可提交，原因可选（PRD 3 第 6 步）。
- 未开启“评价”记录开关时，弹层底部说明“评价不会被记录”，并提供跳过。
- 提交后回到教程页，教程顶部显示“你做过 · 好吃”。

### 4.8 收藏

- 两个分段：**收藏**、**历史**。
- 列表项：缩略图（1:1）、菜名、菜系、做过的标记与评价。
- 已离线保存的教程带“可离线”标记。
- 历史按日期分组；“历史”记录开关关闭时显示空状态说明，而不是空白。

### 4.9 探索（未登录可看）

- 菜系列表：按 4 个分组显示，每个菜系一张卡片（菜系配色色块 + 中英文名 + 一句概述）。
- 菜系详情：概述、典型味型、核心调料（带英文名）、代表技法、代表菜列表、海外替代表；底部 `[ 用这个菜系推荐 ]`，带着菜系选择回到首页第二步。
- 示例教程：每个菜系 1–2 篇，与正式教程同样的页面，可进入烹饪模式；顶部横幅“这是示例教程。登录后可以按你的食材生成。”

### 4.10 我的

- 顶部：显示名、邮箱、今日额度（三项进度：推荐 / 教程 / 拍照，各 x/3），注明“每天 UTC 零点恢复，即你所在时区的 X 点”。
- **我的口味**：一段可编辑的文本（系统归纳 + 用户修改），下面是近期好评与“不会再做”的菜，可逐条移除。
- **做饭习惯**：与欢迎页第一步相同的四个单选问题，改动自动保存；再点一次已选项可取消。列表里显示当前选择的一句话摘要。
- **忌口与过敏**：过敏原以多选标签呈现（花生、坚果、甲壳类与贝类、鱼、蛋、奶、麸质、大豆、芝麻）；忌口用与首页相同的食材输入框。
- **厨具与常备调料**：厨具多选（烤箱、空气炸锅、电饭煲、高压锅、明火灶、电炉/电磁炉、微波炉、搅拌机）；常备调料用食材输入框。
- **数据与隐私**：每类记录一个开关（PRD 7.2），关闭时弹出确认“要同时删除已记录的数据吗？”；[导出我的数据]；[删除全部数据]；[注销账号]（二次确认，需输入“注销”）。

### 4.11 登录层

```
┌──────────────────────────────┐
│ 登录后就能拿到推荐了           │  ← 标题按触发场景变化
│                              │
│ [ G  使用 Google 继续       ] │
│ ───────── 或 ─────────        │
│ 邮箱 [____________________]   │
│ [ 发送验证码 ]                 │
│                              │
│ 小灶目前凭邀请码注册。         │
│ 没有邀请码？申请一个 →         │
└──────────────────────────────┘
```

- 手机为底部弹层，桌面为居中对话框；直接访问 `/login` 时为独立页面。
- Turnstile 无感验证放在“发送验证码”按钮下方，多数情况下不可见；需要挑战时在该位置展开。
- 验证码输入：6 个独立格子，支持粘贴和短信/邮件自动填充（`autocomplete="one-time-code"`）；“重新发送”在 60 秒倒计时后可点。
- **填邀请码页**：一个输入框（自动转大写、忽略空格），错误提示“邀请码无效或已用完”，下方“没有邀请码？申请一个”。
- **申请页**：邮箱（已验证的自动带出）、一句话“想用小灶做什么”（可选）、[提交申请]。

### 4.12 首次登录：欢迎页

两步，顶部显示“1 / 2”“2 / 2”：

1. “先简单了解一下你”：四个单选问题，都可不选——做饭经验（刚开始学 / 会做几道家常菜 / 经常下厨 / 很有经验）、平时做一顿饭花多久（15 分钟内 / 半小时左右 / 一小时左右 / 不赶时间）、能吃辣吗（不吃辣 / 微辣 / 中辣 / 越辣越好）、一般几个人吃（1 / 2 / 3 / 4 / 5 人以上）。说明文字告知“以后在‘我的 → 做饭习惯’里随时改”。底部 [下一步] 与 [以后再说]（保存已选的，跳过第二步）。
2. “有什么不吃或过敏的吗？”过敏原标签 + 忌口输入 + 厨具快速选择。左上 [上一步]；底部 [完成] 与 [跳过这一步]（只保存第一步）。

完成后回到用户原本要去的页面（PRD 7.2“首次使用时询问”）。

## 5. 状态与文案

### 5.1 通用状态

| 状态 | 表现 | 文案示例 |
|---|---|---|
| 加载（列表） | 骨架屏 | — |
| 流式生成 | 内容逐段出现，末尾有闪烁光标 | “正在写步骤…” |
| 图片未就绪 | 菜系配色占位图 + 菜系名 | — |
| 模型出错 | 就地提示 + 重试按钮；额度已退还 | “这次没生成出来，次数已退回。再试一次？” |
| 网络断开 | 顶部细条 | “离线中，收藏的教程仍可查看和烹饪” |
| 个人额度用完 | 主按钮变为不可点的说明 | “今天的 3 次推荐用完了，X 点（你的时间）恢复。可以先看看收藏或示例教程。” |
| 全站预算暂停 | 页面顶部横幅，模型类按钮不可点 | “今天的生成名额已满，明天 X 点恢复。已保存的教程照常可用。” |
| 账号停用 | 登录后显示说明页 | “账号已暂停使用，如有疑问请联系我们。” |
| 识别失败 | 回到手动输入 | “没认出来，手动输入也很快” |
| 推荐被过滤后不足 | 列表末尾说明 | “考虑到你的忌口，这次只找到 2 道合适的。” |

### 5.2 文案规范

- 称呼用“你”；语气像会做饭的朋友，简短、直接。
- 不用感叹号表达热情；不用“亲”“哦～”。
- 数字用阿拉伯数字；时间写“20 分钟”；温度按单位设置显示 °C 或 °F。
- 食材英文名用当地叫法：单位设为美制时显示美式（eggplant），公制时优先英式（aubergine）——依据 `ingredients.yaml` 的 `en.us` / `en.uk`。（可在“我的”中单独设置，P1。）
- 错误提示说清楚发生了什么、额度是否扣了、下一步怎么做。
- 按钮写动作：“给我推荐”“开始做”“换一批”，不写“确定”“提交”。
- 凡消耗额度的按钮，都在按钮上写明“用 1 次，剩 N 次”。

## 6. 视觉规范

### 6.1 风格

**v0.2「灶边手帐」（2026-11-18）**：米纸作底，酱油色作墨，灶火橙只给每屏最重要的那个动作。照片是主角，界面像一本翻旧了的家常菜笔记。

“烟火气”来自目标用户熟悉的厨房物件，而不是鲜艳的颜色：

- 常用食材做成菜市场小标签（带穿绳孔）；已选食材放在“砧板上”（牛皮纸色块），主料是墨色实心带勾。
- 菜系用微微歪着的印章（手写体）标出；“还要买”做成购物小票。
- 步骤的判断标准用姜黄荧光笔划线；关键点是便签，用手写的“一二三”编号。
- 首页按本地时间问候（“周三 · 晚饭时间 / 今晚就做什么”）。
- 配图：45° 或俯拍，窗光加暖色灶灯，粗陶、搪瓷、木桌、格子布，摆盘不刻意，带一点热气。

不用 emoji、渐变铺底和左侧色条卡片。

| `--primary` | #B5421A | #FF8A4C | 灶火橙：主按钮、选中的味型、进度（白字约 5.4:1） |
| `--primary-contrast` | #FFFFFF | #1A1209 | 主按钮上的文字 |

- 深色模式跟随系统，“我的”中可手动切换。

**菜系分组配色**（用于占位图与菜系卡片，饱和度低，避免喧宾夺主）：

### 6.3 字体与字号

- 正文字体栈：`-apple-system, "PingFang SC", "Hiragino Sans GB", "Noto Sans SC", "Microsoft YaHei", system-ui, sans-serif`。
- 标题（Display、H1、H2、菜名、步骤序号）用宋体粗体：`"Songti SC", "STSong", "Noto Serif CJK SC", "Noto Serif SC", "Source Han Serif SC", serif`，只用系统自带字体，不下载。
- 手写点缀：Ma Shan Zheng，只用于标志“小灶”、菜系印章、关键点编号。随站点自托管（`@fontsource/ma-shan-zheng`），按 unicode-range 分片，只下载页面用到的字形；不走 Google Fonts，部分网络访问不到。
- 数字与英文跟随系统字体；用量数字使用等宽数字（`font-variant-numeric: tabular-nums`）以便对齐。

| 级别 | 字号 / 行高 | 用途 |
|---|---|---|
| Display | 28 / 36，粗 | 教程菜名 |
| H1 | 22 / 30，粗 | 页面标题 |
| H2 | 18 / 26，粗 | 区块标题 |
| Body | 16 / 26 | 正文、步骤 |
| Small | 14 / 20 | 英文名、辅助信息 |
| Caption | 12 / 16 | AI 示意图标注、免责说明 |
| Cook | 28 / 40 起，可在烹饪模式内放大到 34 | 烹饪模式步骤 |

正文不小于 16px，避免 iOS 输入框聚焦时页面放大。

### 6.4 间距、圆角、阴影

- 间距以 4px 为单位：4 / 8 / 12 / 16 / 24 / 32 / 48。页面左右边距 16px。
- 圆角：标签 999px（胶囊）；按钮与输入框 12px；卡片 16px；底部弹层顶部 20px。
- 阴影只用于浮起的元素（底部固定栏、弹层、计时器悬浮条）：`0 4px 16px rgba(42,38,34,0.08)`；卡片用描边不用阴影。

### 6.6 动效

- 卡片流式出现：自下而上淡入 200ms。
- 图片替换占位：淡入 300ms。
- 烹饪模式翻页：水平滑动 250ms。
- 遵循系统“减少动态效果”设置，开启时去掉位移只保留淡入。

### 6.7 品牌

- 名称：小灶；英文 Xiaozao。
- 标志（待设计）：方向为一口锅或一簇小火苗的简笔图形，配“小灶”二字；主色灶火橙。PWA 图标需要 192px、512px 和可遮罩版本。
- 一句话介绍：“告诉它你想吃什么味道、手头有什么，它帮你挑几道菜，再带你做出来。”

## 7. 响应式

| 宽度 | 布局 |
|---|---|
| < 768px | 手机布局，底部标签栏 |
| 768–1023px | 同手机布局，内容区居中最大 640px |
| ≥ 1024px | 顶部导航；内容区最大 720px；教程两栏；推荐卡片两列；底部固定栏改为内容区内的普通按钮 |

烹饪模式在桌面端同样全屏，“上一步/下一步”按钮支持键盘左右方向键和空格。

## 8. 无障碍

- 所有图片有替代文本（菜名 +“AI 示意图”）。
- 标签与开关有正确的选中状态语义（`aria-pressed` / `role="switch"`）。
- 流式内容区域使用 `aria-live="polite"`，但只在每道菜或每一步完成时播报，避免逐字朗读。
- 计时器到点除声音与振动外还有视觉提示。
- 支持系统字体放大到 200% 不出现内容截断。

## 9. 管理后台

面向管理员，桌面优先，不追求手机端体验。

- 左侧导航：邀请码、申请、花费、账号、图片库、知识库。
- **花费页**是首页：顶部一条当日预算进度条，标出 $50 / $80 / $95 / $100 四个阈值和当前所处档位；下方按环节分列的当日花费表和近 30 天趋势图。
- 列表页统一为表格 + 顶部搜索 + 行内操作；危险操作（作废邀请码、停用账号）需二次确认。
- 视觉沿用同一套颜色令牌，信息密度更高（正文 14px，行高 20px）。
